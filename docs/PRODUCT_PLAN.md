# 雪雪个人网站 · 产品规划与设计方案 V1.0

> 状态：**第二阶段提案（尚未批准实施）**
> 创建日期：2026-10-28
> 本文件保存 ChatGPT 项目多轮访谈的已确认需求，以及基于现有代码/截图提出的**待确认设计建议**。
> 当前网站代码位于 `goheye/folio` 的 `main`；生产地址：https://folio.3303147509.workers.dev/

## A. 已确认需求（不用重新问）

- 网站目标：**求职优先**，以专业作品集展示为主要方式，同时兼顾商业合作与个人品牌。
- 职业探索方向：编剧与 AI 影视制作结合的复合型创作；尚未最终确定职业头衔，避免过度包装。
- 内容权重：**剧本创作与 AI 影像作品同等重要**。
- 风格目标：**有创意、有个性、有艺术感**；保留精致、令人记住的创作气质。
- 内容开放边界：只公开简介、节选、预告或演示片段；完整作品通过私人联系提供。
- 代表项目：花朝朝/灵植题材短剧，用户自述有 50 集剧本与相对完整的连续剧情视频；尚未独立核验作品品质、归属及可公开权限。
- 用户已参与故事构思、剧本审核修改、角色/场景制作、视频生成；剪辑与后期情况不同项目有所不同，避免宣称全流程专业交付。
- 常用工具：ChatGPT、DeepSeek、豆包、即梦、TapNow、可灵、剪映；工具使用经验属于事实描述，不作为职业资格的自动证明。
- **本阶段不急于修改线上页面；先明确产品方案，再分批开发验收**。
- 不再进行冗长的能力问卷；后续仅在需要真素材、有效联系方式和公开授权时收集最小必要信息。

## B. 已核对的当前实现

GitHub 代码：`src/App.tsx`、`src/styles/globals.css`、`index.html`。
设计依据：`AGENTS.md`、`DECISIONS.md`。
实际视觉：`visual-snapshots` 分支 `snapshots/manifest.md`，2026-10-28 截图对应 commit `00df89aacb`；已检查桌面欢迎页、主页、剧本、影像、关于及手机欢迎页、主页、剧本、弹窗、影像。

### 保留
- 森林里的创作房间、背景摄影/插画、深绿色、玻璃拟态与文字排版。
- 欢迎页的仪式感、书架式剧本卡片、桌面侧栏 / 手机底栏。
- 单页静态架构、React/Vite/Tailwind 与 GitHub Actions → Cloudflare 发布链路。
- 项目 `AGENTS.md` 中既有设计令牌和不过度装饰的规范。

### 需要改善
- 首页文字过于抒情，尚不能在短时间内说明“剧本 + AI 影像”专业方向。
- 第一次进入需要点击“进入”，对于招聘者可能增加路径成本；应保留仪式感但提供可直接看代表作的入口。
- 剧本区是三个硬编码示例 `候鸟以北`、`凌晨四点的海`、`无声来电`；未经核实，不应当成真实个人履历作品展示。
- 影像区是渐变色文字卡片，未接入真实视频、封面、片长、制作信息。
- 关于区的 `hello@example.com` 是占位联系方式，必须替换或暂时隐藏。
- 手机作品页是纵向长列表，需优化扫读、节选与视频可访问性；不能靠桌面效果判断移动端质量。
- 作品没有统一的“我的职责／AI 协作方式／完成度／公开范围”描述。

## C. 信息架构提案（待确认）

推荐先保留现有 5 栏导航，以小改代替整站重写：

1. **主页**：可快速识别的个人定位 + 剧本与 AI 影像双入口 + 1–2 个精选作品 + 联系动作。
2. **剧本**：真实作品列表，允许阅读合适的精选节选，不暴露完整剧本。
3. **AI 影像**：真正的视频片段、封面、项目关联说明与个人负责环节。
4. **创作手记**（由现有“灵感”改造；可放后期）：人物设定、场景、分镜、前后版本比较，展示创作过程与判断力；不必写成 AI 工具教程。
5. **关于 / 合作**：简洁真实的个人介绍、主要创作方向、联系渠道、私下索取完整作品的说明。

不建议第一版新增后台、账号登录、复杂博客或视频上传平台。当前静态站足以完成主要展示目标。

## D. 关键页面设计提案（待确认）

### 1. 欢迎屏
- 保留森林和创作房间主题、光影与仪式感。
- 简化抒情文案，增加身份可理解度。可选文字方向（**未定稿**）：
  - 主视觉：`让故事，从文字走向画面。`
  - 副文案：`剧本创作 · AI 影像实验 · 作品精选`
- 同时提供“进入创作房间”和“直接看作品”路径，不以进入动画阻拦招聘方；需保证首屏访问快。

### 2. 首页
- 首屏 10 秒内回答：我是谁 / 我的作品类型 / 去哪看作品 / 如何联系。
- 剧本与 AI 影像两个入口视觉平衡，不只把剧本做成唯一主卡。
- 精选一项真实代表项目并明确状态（例如“剧本节选”“片段演示”），不虚构奖项、播放量、商业交付经历。
- 可选一个“从故事到镜头”的设计亮点，其他动画克制。

### 3. 剧本
每个项目的结构建议：
`封面 / 作品名 / 类型 / 核心设定 / 集数（核实） / 当前状态 / 我的贡献 / 精选片段 / 获取完整版方式`。
- 花朝朝项目优先作为候选；若参考已有作品，公开前核对改编来源、权利和描述。
- 试稿可在授权/适当范围下作为工作样本，不等同于已商业发行的项目。
- 不提供可通过浏览器资源直接下载的完整保密剧本；前端弹窗/隐藏按钮不能保护已发布的源文件。

### 4. AI 影像
每个视频项目的结构建议：
`真实封面 / 演示视频 / 时长 / 关联剧本 / 创作职责 / 制作环节 / 观看说明`。
- 能实际播放才标“视频作品”；尚无素材的条目标记为筹备，不用渐变占位冒充作品。
- 显示“人物设计、场景、视频生成”等已核实职责，不夸称自己完成全部后期。
- 手机端采用原生视频控制、poster、懒加载；视频与完整剧本私下提供的规则需区分。
- 大视频可以用合适的对象存储/CDN，暂不引入服务端框架。

### 5. 创作手记
- 用真实小案例说明：问题 → 修改方法 → 结果；可涉及角色身份混淆、站位与首尾帧控制。
- 成功和失败都真实记录，突出设计判断而非夸大工具熟练度。

### 6. 关于 / 合作
- 真实、精炼的中文自述，避免未经证明的“资深编剧／独立完成商业全流程”等用语。
- 显示可确认的有效邮箱/联系方式与简洁的“索取完整作品”“交流合作”动作；没有真实渠道前不展示示例地址。
- 不自动公开个人隐私、未授权联系方式、未定稿作品素材。

## E. 视觉与交互原则（待确认）

- 主题沿用森林创作房间，保持原有色彩与设计令牌（见 `AGENTS.md`）。
- 设计关键词：**艺术感 / 有生命力 / 作品驱动 / 克制的沉浸感**。
- 内容可读性优先：避免透明玻璃导致长文对比度不足；作品介绍留白清晰。
- 仅一个记忆点动效，支持 `prefers-reduced-motion`；谨慎处理首屏背景大图加载。
- 手机端第一屏应显示明确身份/作品入口，底栏不遮挡内容与视频控制。
- 桌面/手机、键盘操作、弹窗焦点、触屏播放及暗弱网络需验收。

## F. 按优先级实施（不在本方案阶段直接修改页面）

### P0 · 内容可信度与求职可用性（最高优先）
- 确认真正可以公开的代表剧本、节选、视频片段及封面。
- 清理/标注未核实的示例作品与虚构时长，删除示例联系邮箱。
- 明确“可申请完整版”，但不公开完整文件。

### P1 · 首页与导航
- 重新组织欢迎页/首页文案、剧本+影像双入口、精选作品。
- 保留整体设计语言，改善第一屏信息传达与路径效率。

### P2 · 两类作品页 + 代表项目详情
- 剧本内容统一数据结构、精读/节选展示。
- AI 影像接入真实演示片段，增加与剧本项目的关联。
- 选 1 个真实项目完成高质量案例页，再推广到其他项目。

### P3 · 关于、优化和验证
- 实际联系方式、手机体验、加载性能、无障碍、SEO/OG 分享信息。
- GitHub Actions `npm run lint`、`npm run build`、生产部署状态、截图/交互复核。

### 未来而非当前必须
- 个人创作日志、双语、管理后台、私密文件授权访问、复杂动态交互。

## G. 第一版验收标准（建议）

- 新访客约 10 秒能理解创作方向。
- 在不超过 2 次操作内分别到达真实剧本节选和真实 AI 影像片段。
- 联系渠道真实可用；完整作品未被公开资源暴露。
- 不使用虚构作品/资历/播放量/奖项或未经核实的原创性表述。
- 手机约 390px、桌面约 1280–1440px 排版可用，视频与弹窗不被遮挡。
- 视觉语言和旧版保持关联；lint/build 通过，并核实实际部署和最新截图。

## H. 下一次推进时只需要的素材（不需要立刻全部提交）

- 至少 1 个**允许公开**的剧本项目：正式名称、1 段简介、1 份公开节选和创作归属描述。
- 至少 1 个**允许公开**的 AI 视频片段：文件或真实可访问链接、封面、是否可以公开。
- 一个真实可用的对外联系渠道（无需公布私人手机号）。
- 其他作品可后补；在授权、内容与真实性未确认前保持候选状态。
